# 公开发布边界

AH Note是公司研究唯一的读者入口。`stock_report`提供已校验研究成果和历史追溯，但其Git文件地址不作为报告交付链接。

当前公司研究协议为`stock-research-analysis-v4`，并继续读取尚未重跑的v2/v3结果。站点只接纳五项Sol核心自审全部通过、关键计算字段完整且正文存在的结果；v3要求3—5年连续历史，v4默认三年但允许新上市公司按实际可得的一至五年连续上市后历史，两者都要求非空的最新年度业务拆分。同一证券选择最新报告期，同一报告期按v4、v3、v2、统一v1和旧版顺序取最高协议。站点只做协议映射和Markdown展示，不修改经营数字、估值或中心判断。

`/reports/<code>/`展示当前公司研究。`/research/`聚合当前协议报告与历史深度研报：当前报告链接到`/reports/<code>/`，历史报告仍链接到`/research/<code>/<version>/`。同一证券、同一报告期重复时优先当前协议。历史地址继续保留通过独立注册表、审阅状态和正文哈希验证的不可变文章；两类内容都属于AH Note公开站点，但来源准入不同。

`/capital/`展示独立的资本表年度数据。`scripts/publish_capital_statement.py`只接纳通过协议校验的年度JSON，以内容哈希保存原件，更新公司年度清单及全站目录；网页只负责确定性渲染，不重新解释或修正数字。v3/v4必须包含事实账本、经济映射和显示注册表，扩展字段每年最多5个。新增年度增量导入，不要求重做同公司其他年份。

远端发布服务使用干净的`stock_report`镜像和独立的`stock_analysis_site_source`镜像，逐轮快进同步后再检测稳定且可发布的成果。站点输入不得指向经营分析A/B槽、活动Bundle或其他会随调度切换和清理的运行目录。每次发布从远端最新`main`创建一次性 Git worktree，在其中完成构建、提交和推送；输入、构建或推送失败时销毁整个 worktree，不能污染常驻站点 checkout，也不能推进监听状态。推送失败最多退避重试三次，每次重新读取远端基线并构建。

研究列表页直接进入文章列表，不展示宣传性页头。该要求固化在生成模板和回归测试中，不能只修改生成HTML。

`/industries/`读取`stock_analysis`的版本化 A/H/美股共同树配方，不从报告正文反向猜测行业。构建在临时目录应用精简决议及批量证据，验证后压缩为一份公开 JSON，退出即清理临时物化；前端只负责搜索和层级展示，不改写分类事实。批量映射、行业校准和公司核实是不同证据等级：有唯一主类的基础映射可进入浏览，但不能显示成已核实；没有唯一主类的对象留在异常列表。经营宽类拆分后出现的`other`残余叶照实展示，它表示当前分类粒度，不等于无分析价值。

发布监听摘要覆盖配方内的`source`、`decisions`、可选`sec_evidence`和可选`taxonomy_extension`，以及生成代码与A/H名称/代表补充。内容变化才触发构建，生成时间和无关Git提交不参与摘要。输入缺失或构建失败不得回退旧分类，也不得推进状态。

公开行业树折叠连续同名的父子节点，例如底层的“能源→煤炭→煤炭→煤炭”显示为“能源→煤炭”。折叠只影响展示节点和导航，源 HSICS 层级、代码和发行人主分类不变。

发布器是常驻 Python 进程。每轮巡检先快进站点仓；如果代码发生变化，必须先自重启重新加载模板，再生成页面，避免内存中的旧模板覆盖新导航。成果摘要状态不能单独作为“已经发布”的证据：每个可发布证券还必须存在`/reports/<code>/index.html`，状态已记录但页面缺失时自动重新发布并在成功后重写状态。
